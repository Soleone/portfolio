# GitHub projects review

Source: https://github.com/Soleone
Fetched: 2026-06-13

Goal: pick which GitHub projects should become portfolio entries. Initial portfolio data only needs title, description, and source link. Later passes can add live deployments and representative images/screenshots.

## Review key

- `yes`: include in first portfolio pass
- `maybe`: keep in backlog, review later
- `no`: skip for now
- `deploy`: good candidate to try making always-live
- `download`: host release to download and try locally 
- `image?`: needs representative screenshot, generated UI capture, repo social preview, or custom card

## Priority key

- `high`: strongest fit for the first portfolio pass or flagship narrative
- `mid`: useful supporting entry, backlog candidate, or grouped project
- `low`: likely skip, archive, duplicate, or only mention elsewhere

## Screenshot and image strategy

For each portfolio project, store one image path in project data, ideally under `public/projects/github/<repo>.png`.

Suggested image sources in priority order:

1. Live app screenshot if deployable.
2. Local app screenshot after running the project.
3. Existing README image or GitHub social preview.
4. Generated visual card for libraries, CLIs, bots, and Unreal projects that cannot be deployed.
5. Architecture diagram for agent/tooling projects.

For deployment, use the always-live approach from `/home/soleone/src/tries/2026-05-26-always-live`: each project should eventually have a small manifest with repo, build command, run command, health check, screenshot command, and current live URL.

Potential manifest fields:

```ts
{
  slug: "pi-tasks",
  title: "Pi Tasks",
  source: "https://github.com/Soleone/pi-tasks",
  liveUrl: null,
  image: "/projects/github/pi-tasks.png",
  deployability: "docs-demo | static | vercel | container | manual | not-deployable",
  screenshotMode: "browser | terminal | generated-card | diagram | manual"
}
```
